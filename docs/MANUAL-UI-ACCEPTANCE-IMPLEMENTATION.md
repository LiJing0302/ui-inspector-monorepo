# 人工元素验收：接入与使用

## 默认口径

设备应有值统一按以下公式计算：

**设备应有值 = Figma 设计原值 × 设备页面逻辑宽度 ÷ Figma 页面宽度。**

宽度、高度、圆角、描边宽度、字号、行高、字距及元素间距均使用同一个宽度比例计算设备应有值。原始运行时值仍为 Android dp／iOS pt。面板单侧属性、diff、属性来源和画布间距统一展示对齐设计稿后的 px：**App 原始逻辑值 × 设计稿宽 ÷ 截图逻辑宽**，与画布使用同一宽度缩放；设计原值保持 Figma px，不乘导出倍率，也不乘画布缩放。diff 的应有值经过相同的显示换算。仅改变显示口径，判定仍使用未取整的原始逻辑值；详情保留原始 dp／pt、SDK 原始物理矩形与物理像素换算。缺少有效设计稿／截图逻辑宽时保留原始单位。颜色、透明度、文本内容等非长度属性不缩放。

例如设计节点 `706:13558` 宽 24 px，App 采集 69 物理 px、密度 3，则原始值为 23 dp；375 px 设计稿与 360 dp 截图对齐后展示 `23 × 375 ÷ 360 = 23.9583 px`。设备应有值 23.04 dp 对齐后展示 24 px；仍显示「存在偏差」。截图逻辑宽若与设备页面宽不同，显示换算继续按截图宽对齐画布，应有值计算仍按设备页面宽执行，不将截图宽冒充设备适配规则。

这是平台采用的验收约定，不是从源码推断出的实现策略。计算不读取 SDK 的 `acceptanceContext.design`、自定义适配视口、节点 `acceptanceRules` 或取整策略，也不根据元素实测值反推目标。不要求开发先调用 `configureAcceptance`；没有这些声明的旧快照也可以计算目标。

### 示例：375 设计稿 → 360 dp 页面

| 属性 | 设计原值 | 设备应有值（原始） | App 实测值（原始） |
| --- | ---: | ---: | ---: |
| 宽度 | 100 px | 96 dp | 96 dp |
| 高度 | 44 px | 42.24 dp | 42.3333 dp（原始 127 px ÷ 3） |
| 圆角 | 12 px | 11.52 dp | 11.52 dp |
| 字号 | 16 px | 15.36 dp | 16 dp |
| 间距 | 16 px | 15.36 dp | 15.3333 dp |

应有值保留连续逻辑值，不按设备密度取整。表中最多显示四位小数，计算使用原始精度。高度示例即使只差 0.28 个物理像素，也显示「存在偏差」；不以物理像素阈值放宽判断。

## 验收人员的流程

1. 从 Figma 插件导出并在 Mac 平台导入设计稿，从 RN App 上传页面。插件保留原始页面尺寸、元素属性及固定 / HUG / FILL 尺寸意图；SDK 采集页面窗口、原始节点矩形、样式、平台、密度等环境与实测信息。
2. 在画布选中设计元素，按 ⌘/Ctrl 点选另一侧对应元素，右栏显示「属性 / 设计原值 / 设备应有值 / App 实测值」。表上方说明公式，展开验收环境可查看本次计算的设计稿宽度与页面宽度。
3. 在同一侧选中一个元素，再按 ⌘/Ctrl 点击另一个元素固定间距。两侧各固定一对后，右栏对照对应的边界距离。0、小于 0.5 的距离仍在表中显示；负间距表示重叠。它们是布局框之间的距离，不代表已读取源码 padding / margin。
4. 检查外观、裁切、换行等效果。发现问题后点击「记录问题」，填写描述、可选截取画布。系统保存当时的设计值、应有值、实测值、计算口径、SDK 版本及关联元素；打开表单后切换选中项不会改变已冻结的证据。
5. 展开「物理像素与验收环境」排查原始矩形和密度。Mac 画布缩放、PNG 导出倍率都不改变 dp/pt 读数。设计稿导出 2x 只增加图片像素，不会把设计原值乘二。

## 叠图交互与节点预览

叠图验收模式下，从截图内开始拖拽只移动截图，设计稿与视口平移保持不动；从截图外开始拖拽平移整个画布，同时移动设计稿与截图，保持两者相对位置，可将叠图移至画布中央。手势按按下位置确定，跨越截图边界不会切换操作。单击不选中元素，也不清除已有选中。叠图时隐藏节点选中框、悬停框、关联高亮及测距，切回全页验收后恢复已有选中。方向键微调截图，Shift + 方向键移动 10 个画布单位。需要在画布点选节点时切回全页验收。

全页验收中两侧各选一个节点、进入属性 diff 后，右栏底部固定显示「节点叠图」。预览显示两侧真实底图中的选中区域及少量周边，保留边界附近的描边、阴影和背景；截图按设计稿页面宽 / 截图页面宽等比缩放，再将选中节点左上角对齐；不按节点各自宽高拉伸，因此宽高差异仍可见。蓝框为设计稿、橙色虚线为 App，可拖动截图透明度查看两侧，切换节点后自动重新对齐。预览不受主画布缩放、平移或全页叠图手动偏移影响，不修改原始节点、属性应有值或问题关联。

节点叠图支持滚轮围绕指针缩放、加减按钮缩放。从橙色 App 截图节点框内开始拖拽只移动截图及其节点框，设计稿固定；从节点框外开始拖拽平移整个叠图画布，保留两侧相对偏移。按下时决定操作，拖动跨越边界不切换。「恢复对齐」清除截图偏移，恢复节点左上角对齐；「适应」或双击画布仅恢复视口居中与适应大小。缩放范围为适应视图的 25%–1600%，显示比例相对于适应大小，不代表物理像素倍率；缩放不改变两侧相对偏移和节点尺寸。画布获得焦点后可用加减键缩放，方向键微调截图 1 个画布单位，Shift + 方向键移动 10 个，0 复位视口。

点击预览标题旁「放大」打开居中弹窗，弹窗与小预览共用缩放、平移、截图偏移和透明度设置，弹窗画布随窗口尺寸适应。弹窗支持相同操作，关闭按钮、Esc 或点击遮罩关闭；Tab 在弹窗内循环，关闭后焦点回到放大按钮。关闭保留预览设置，切换对比节点后复位。手动偏移时标题显示「手动偏移」。操作预览不改变主画布、节点选择、原始几何或 diff 数值。

缺图、无效节点尺寸或加载失败时显示无法预览的原因。单节点、测距、叠图模式及其他右侧页签不显示此预览。

## 重合元素的样式汇总

选中节点有可见、有面积且矩形严格相同的关联图层时，右栏显示「由 N 层组成」，默认进入「元素汇总」。Android / iOS 共用规则：同父的兄弟及直接父子关系组成连通的重合检查组，不再要求父层只有一个子节点或其中一层无样式。自身开启裁剪、拥有圆角、填充、文本或其他样式不影响入组；隐藏、被完全裁没或矩形不同的节点不参与，也不能作为桥梁连接其他分支。设计稿保留同父兄弟分组。App 优先用 SDK 原始 `pixelRect` 分组；设计稿与旧快照用原始逻辑矩形。有／无 `pixelRect` 不混组；不设 0.5 或其他几何容差。

入组只表示位置重合，不代表属性一致或已计算最终叠加外观。各层仍保留原始节点和属性来源，按属性分别处理。已采集、明确无背景绘制的圆角／裁剪容器不阻止读取另一层的渐变；该容器自身的圆角仍参与圆角冲突判断。两个完整圆角值即使格式化后显示相同，只要原始值不同也保留冲突，不因同框而覆盖。

插件现在保留已采集的空 fills／strokes／effects 数组，供平台确认无绘制壳；旧稿缺失这些通道时保持未知，不推断为没有。容器还需明确未启用裁剪。

侧栏统一只展示明确值，数值 0 保留。 App 的 `style:null`、圆角／描边宽度空对象或空槽不再补为 0；只有四角／四边均为完整有限数字时才形成该属性的实测值。文本节点与容器使用同一规则。单节点、单层属性隐藏无明确值的属性；元素汇总同时检查参与汇总的原始图层是否有明确值，冲突不能导致已采集值被隐藏。diff 在设计侧或 App 侧（包括参与汇总的候选层）至少一侧有明确值时展示该行，两侧都没有则隐藏，保留真正无值的单元格留空。顶部统计只计算可见行。不提供隐藏属性的展开入口；原始属性和问题证据仍保留。

圆角对比采用无圆角等价约定：设计四角均为 0、App 圆角未设置（样式或圆角字段缺失／为 null、四角均为空）时显示「数值一致」，应有值为 0，App 实测单元格仍留空。该约定不补写原始数据、不扩展到描边宽度；部分角有值而其余缺失、非零设计圆角或多层属性来源有歧义时仍保留「信息不足」。

Figma TEXT 的 fills 绘制文字字形，不能当作节点背景与 App 的 backgroundColor 比较。侧栏保留文字颜色，不重复显示为背景填充；App 独立采集的背景色仍保留在单侧及 diff 中。原始文本 fills 不修改。

文本节点的宽高在 diff 中仅展示设计原值、应有值和 App 对齐值供参考，不标黄、不显示状态标签、不参与一致／偏差／待确认／信息不足等统计；固定与动态文本框使用同一规则。任一侧明确为文本节点时适用。缺少的单元格仍留空，两侧都无值仍隐藏该行。字号、字重、行高、字距、颜色等继续正常比较；容器宽高维持原判定。换行、截断、位置和占位范围通过节点叠图人工检查。

描边宽度须先确认当前节点启用了描边 paint。空描边、全部隐藏／完全透明、节点透明度为 0，或旧稿明确 `hasFill:false` 且没有描边 paint 时，不生成数值宽度目标。原始 `strokeWeight` 保留在设计数据中。旧稿缺少 paint 信息、又没有明确无绘制证据时保持未知；已启用描边但宽度缺失或无效时也保持未知。无描边及未知状态均按上述无明确值的展示规则处理。有描边的矢量仍按原宽度与页面比例计算，不能仅因元素是 SVG 就隐藏属性。App 是否出现额外描边仍需人工看图检查。

单侧和双侧对比使用同一套解析，两侧分别寻找自己的属性来源。例如点击壳已确认无盒外观，另一层持有 11.52 dp 圆角，在 375／360 的宽度比例下，汇总、对比和来源列表都会展示 12 px，并注明来源。宽高仍来自真实选中节点；间距、原始树和节点关联不变。

有相关绘制层未采集属性，或多个值不同（包括 0 与非零）时，解析结果仍标记「多层待确认」，不自动判为一致。只要参与汇总的图层中存在明确值，侧栏和 diff 就保留属性行及该侧的「查看各层数值」入口；展开可见各层值、来源和数值属性的完整原始读数。所有相关层都无明确值时继续隐藏，不把未知当作 0 或制造汇总值。问题证据保留各层候选值。文本内容与字体、描边色与宽度不能从不同层拼成一份属性。渐变、透明叠加、图片和自绘的最终效果仍由人工看图。

「单层属性」只检查当前原始层；展开「查看 N 个原始图层」点选某层也会进入该模式。两侧可独立选择范围。问题记录在打开表单时冻结原始 anchor、检查范围、组成员、候选值和解析状态，切换范围与节点不会改写这份证据。

## 页面宽度与截图宽度

页面宽度来自采集时的原生窗口物理宽度除以原生密度，作为设备环境信息使用。它独立于截图画布尺寸。例如窗口 1080 px、密度 3，则页面宽度是 360 dp；即使上传截图宽 1200 px，应有值仍按 360 / 375 计算，画布继续使用截图自身的尺寸。

新采集保存 `devicePageWidth`。历史快照优先从已保存的 `coordinateInset.sdkWidth` 与原生密度还原；窗口与截图一致时用截图物理宽度 / 密度，再缺失则使用保存的逻辑宽度。不会使用 SDK 自定义的适配视口替代原生窗口。历史元数据没有记录的窗口差异无法事后恢复。

## 提示的边界

- 数值一致：完整属性与目标相等，只排除浮点运算本身的机器精度残差，不设逻辑单位或物理像素容差。
- 存在偏差：目标与完整实测属性有差异。
- 信息不足：缺少有效页面尺寸或属性、旋转 / 估算框、复杂填充、两侧测距关系不对应等。能够按设计比例计算时仍展示应有值，作为参考。容器的 HUG / FILL / STRETCH / SCALE 只作布局说明，不阻止按当前设计框与页面宽度比例比较。文本宽高仅供参考；系统字体缩放不是默认值时，字体长度暂不自动判断，但不改变设计推算的应有值。

SDK 的可选 `configureAcceptance` 与原有规则字段保留兼容，仅作为归档信息；本人工验收流程无需配置它们。SDK 没有新增从图片反推圆角、读取任意源码属性或完全重建 Yoga 布局的能力。
