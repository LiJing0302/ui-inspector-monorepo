## 三、这份答案能换回什么（反向优化映射）

这是你问的重点。每一份答案都对应一个**可计算的优化动作**，不是"有了心里有底"。

### 从 T1（33 个锚点）反推

1. **阈值从"拍"变成"算"**。引擎的诊断输出里每对已经有 6 个证据分量（`geometry / structure / relation / visual / content / kind`）。有了 33 个正例，就能画出正例的分数分布；配合 T2 的难负例画负例分布，**取最大 F1 的切点**。现在的 `match: 0.38 / autoMatch: 0.85 / autoMargin: 0.12` 全是我拍的。
2. **证据权重拟合取代手打分**。把那 6 个分量当特征、33 正 + N 负做逻辑回归（或网格搜索），得到权重向量。输出是可解释的（"geometry 0.42 / content 0.31 / structure 0.15 …"），而不是一个黑盒分数。
3. **留一法给出"种子数 → 召回率"曲线**。每次留 1 个锚点当查询、其余当种子，看能不能找回来。**这条曲线直接回答"相似度泛洪要几个种子才收敛"**，也决定要不要上视觉证据通道。现在完全没有这个数据。

### 从 T2a（9 组重复文案：¥259×8、标题两行×6 …）反推

- **决策规则**：若几何消歧对重复文案的成功率 <70%，就说明光调几何权重救不了，**必须引入同序约束（兄弟相对次序不得交叉，LIS 式）**。这条比继续调权重有效得多。

### 从 T2b（44 组同形兄弟）反推

### 从 T4（7 条屏幕级差异）反推

- 决定"哪些差异算 issue"。没有它，覆盖率再高也可能全是噪声。
- 建立**回归基线**：以后每次改引擎，跑一遍看 verdict 有无变化 —— 这是唯一能防"改好了 A 弄坏了 B"的手段。

### 跨全部的一条（最重要）

**迭代方式从 open-loop 变成 closed-loop。**

现在的循环是「改一条规则 → 看总数变没变」。这个信号太弱：**总数可以完全不变，但错的全换了一批**。这正是过去几轮"改了但说不清有没有变好"的根本原因。有了 T1/T2 就能算 precision / recall / F1，**每次改动都有方向**；有了 T3/T4 就能算结构指标（Container Match 的 IoU、TreeBLEU、TED）。

### 参考：这些做法在领域里已有先例

- **相似度泛洪（Similarity Flooding, Melnik et al., ICDE 2002）**：把"两边节点相似 ⇔ 它们的邻居相似"写成定点迭代。这是我们现在那套"定向 BFS 扩散"的严格版本，好处是**可以从任意位置流动，不依赖"组首必须有子节点"这种脆弱前提**。
- **design-drift 的 `auto-match`**（跟这个任务几乎同题）：文本锚点先做 Theil–Sen 全局仿射估计 → 文本/几何/结构/样式加权打分 → **层级约束下的全局指派**；在"层名毫无意义的未插桩应用"上自动配上 162 对，只 3 对要人工复核；阈值是在 6300+ 对抗性诱导错配上校准出来的。**"靠人工复核条数衡量质量"这个口径值得我们直接抄。**
- **DETR 风格的代价矩阵 + 匈牙利**：`L = γ_class·L_class + γ_box·L_box`（类别损失 + 框损失），一次求全局最优指派。我们现在是逐层贪心，所以上一层吃错下一层全废。
- **Apple Screen Recognition** 的分组启发式把元素数降了 48.5%（21.8 → 12.1/屏）—— 说明"把碎片合成元件"这个动作本身就能把噪声砍一半，跟 T3 要验证的是同一件事。

### 顺带一个实际收获（不是假想）

准备这份表的时候，从数据里直接坐实了一个**真缺陷**：设计第二个双行条目是「积分商城 / 好礼兑不停」，
App 里写成了「积分商城 / **福利天天领**」（跟左侧条目重复）。详见 T4 第 4 条。

它同时暴露了一个**可以立刻写进引擎的判据**：`福利天天领` 在 App 侧出现 2 次、设计侧 1 次；
`好礼兑不停` 设计侧有、App 侧没有 —— **「一侧重复 + 另一侧缺失」这个组合本身就是高置信信号**，
它比单报一条 missing 有用得多，因为它直接告诉你"多余的那一个是什么"。现在的引擎只会把它拆成
一条 missing + 一条 extra，用户看到两个孤立事实，而不是"副标题写串了"。
